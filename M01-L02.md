### Урок M01-L02: CLR, IL, JIT, сборки / CLR, IL, JIT, Assemblies

**Время / Time:** 30 мин теория + 45 мин практика

#### Теория / Theory

Когда вы пишете `Console.WriteLine("Hello")` на C#, этот текст не превращается сразу в машинный код вашего процессора. Вместо этого происходит двухэтапное путешествие.

**Этап 1: компиляция в IL.** Компилятор C# (Roslyn, `csc`) читает ваш `.cs`-файл и переводит его в промежуточный язык — Intermediate Language (IL, он же MSIL или CIL). IL — это «байткод» .NET, аналог байткода Java. Это не инструкции конкретного процессора (x86, ARM), а универсальный, платформо-независимый набор команд. Вместе с IL компилятор генерирует **метаданные** — описание всех типов, методов, полей и их сигнатур. Результат упаковывается в **сборку** (assembly) — файл `.dll` или `.exe`.

**Этап 2: JIT-компиляция.** Когда вы запускаете программу, CLR не исполняет IL напрямую. JIT-компилятор (Just-In-Time) «на лету» переводит каждый метод из IL в нативный машинный код вашего процессора, причём только когда метод впервые вызывается. Это похоже на устного переводчика на конференции: он не переводит всю речь заранее, а переводит каждую фразу по мере необходимости. Последующие вызовы того же метода используют уже готовый нативный код из кэша — поэтому повторный проход по тому же коду быстрее. В .NET 8 есть и AOT-компиляция (NativeAOT), которая компилирует заранее, но это отдельная история.

**CLR — «операционная система» для вашего кода.** Common Language Runtime берёт сборку, загружает её, верифицирует IL на типобезопасность и обеспечивает среду исполнения: управляет памятью, потоками, исключениями и безопасностью. Главная звезда CLR — **сборщик мусора** (Garbage Collector, GC). GC автоматически освобождает память, занятую объектами, на которые больше никто не ссылается, избавляя вас от ручного `free`/`delete` и утечек памяти, характерных для C/C++.

**Сборки (.dll / .exe).** Сборка — это единица развёртывания и версионирования в .NET. Она содержит IL-код, метаданные и **манифест**. Манифест — это «паспорт» сборки: её имя, версия, культура, публичный ключ (для подписанных сборок) и список зависимостей от других сборок. Благодаря метаданным сборка «самоописывающаяся» — вам не нужны внешние заголовочные файлы (как в C++), а типы можно открыть через рефлексию. `.exe` — исполняемая сборка с точкой входа (`Main`); `.dll` — библиотека классов без точки входа.

**Зачем так сложно?** Двухэтапная компиляция даёт переносимость (один IL работает на Windows, Linux, macOS, x86 и ARM), интероперабельность (C#, F#, VB компилируются в общий IL и могут вызывать друг друга) и безопасность (CLR верифицирует IL перед исполнением).

#### Theory (EN)

When you write `Console.WriteLine("Hello")` in C#, that text does not instantly become machine code for your CPU. Instead, it goes on a two-stage journey.

**Stage 1: compilation to IL.** The C# compiler (Roslyn, `csc`) reads your `.cs` file and translates it into Intermediate Language (IL, also called MSIL or CIL). IL is .NET's "bytecode", analogous to Java bytecode. It is not the instruction set of any specific CPU (x86, ARM) but a platform-independent, universal set of instructions. Along with the IL, the compiler emits **metadata** — a description of every type, method, field, and signature. The result is packaged into an **assembly** — a `.dll` or `.exe` file.

**Stage 2: JIT compilation.** When you run the program, the CLR does not execute IL directly. The Just-In-Time (JIT) compiler translates each method from IL into native machine code for your CPU, but only the first time that method is called. Think of an interpreter at a conference: they do not translate the whole speech in advance, they translate each sentence as it is needed. Subsequent calls to the same method reuse the already-compiled native code from a cache — which is why the second pass through the same code is faster. .NET 8 also offers AOT compilation via NativeAOT, which compiles ahead of time, but that is a separate story.

**The CLR — an "operating system" for your code.** The Common Language Runtime loads the assembly, verifies the IL for type safety, and provides the execution environment: memory, threads, exceptions, and security. Its star feature is the **Garbage Collector** (GC). The GC automatically frees memory occupied by objects that are no longer referenced by anyone, freeing you from manual `free`/`delete` and the memory leaks so common in C/C++.

**Assemblies (.dll / .exe).** An assembly is the unit of deployment and versioning in .NET. It contains IL code, metadata, and a **manifest**. The manifest is the assembly's "passport": its name, version, culture, public key (for signed assemblies), and the list of dependencies on other assemblies. Thanks to metadata, an assembly is self-describing — you do not need external header files (as in C++), and types can be opened through reflection. An `.exe` is an executable assembly with an entry point (`Main`); a `.dll` is a class library without an entry point.

**Why so complex?** The two-stage compilation gives portability (one IL runs on Windows, Linux, macOS, x86 and ARM), interoperability (C#, F#, and VB compile to a common IL and can call each other), and safety (the CLR verifies the IL before executing it).

#### Пример кода / Code Example

```csharp
// M01-L02: Демонстрация IL, сборок и метаданных
// Demonstrates IL, assemblies, and metadata via reflection

using System.IO;
using System.Reflection;

// Top-level statements (.NET 8 / C# 12) — точка входа Main генерируется неявно
// Top-level statements (.NET 8 / C# 12) — the Main entry point is generated implicitly

// 1. Информация о текущей сборке (манифест)
// 1. Information about the current assembly (manifest)
Assembly assembly = Assembly.GetExecutingAssembly();
Console.WriteLine($"Сборка / Assembly: {assembly.GetName().Name}");
Console.WriteLine($"Версия / Version: {assembly.GetName().Version}");
Console.WriteLine($"Расположение / Location: {assembly.Location}");

// 2. Исследование метаданных через рефлексию
// 2. Exploring metadata through reflection
Type greetingType = typeof(Greeting);
Console.WriteLine($"\nТип / Type: {greetingType.FullName}");
Console.WriteLine($"Атрибуты / Attributes: {greetingType.Attributes}");

// Перечисляем методы и их параметры — это и есть метаданные
// Enumerate methods and their parameters — this is the metadata
foreach (MethodInfo method in greetingType.GetMethods(
             BindingFlags.Public | BindingFlags.Instance | BindingFlags.DeclaredOnly))
{
    var parameters = string.Join(", ",
        method.GetParameters().Select(p => $"{p.ParameterType.Name} {p.Name}"));
    Console.WriteLine($"  Метод / Method: {method.ReturnType.Name} {method.Name}({parameters})");
}

// 3. Вызов метода — здесь CLR JIT-компилирует IL в нативный код
// 3. Method call — here the CLR JIT-compiles IL into native code
var greeter = new Greeting();
string message = greeter.Format("NET 8", count: 3);
Console.WriteLine($"\nРезультат / Result: {message}");

// 4. Pattern matching (C# 12) для определения типа сборки по расширению
// 4. Pattern matching (C# 12) to detect the assembly kind by extension
string kind = Path.GetExtension(assembly.Location) switch
{
    ".dll" => "Библиотека / Library (.dll)",
    ".exe" => "Исполняемый файл / Executable (.exe)",
    _      => "Неизвестно / Unknown"
};
Console.WriteLine($"Тип файла / File kind: {kind}");

/// <summary>
/// Простой тип, метаданные которого мы изучаем.
/// A simple type whose metadata we inspect.
/// </summary>
public class Greeting
{
    public string Format(string name, int count)
    {
        // Raw string literal (C# 11+) для многострочного шаблона
        // Raw string literal (C# 11+) for a multiline template
        string template = """
            Привет, {0}! Повторено {1} раз(а).
            Hello, {0}! Repeated {1} time(s).
            """;
        return string.Format(template, name, count);
    }

    public bool IsValid(string? input) => !string.IsNullOrWhiteSpace(input);
}
```

#### Best Practices

- Изучайте IL через инструменты: `ildasm`, ILSpy или веб-сайт sharplab.io — понимание IL помогает читать ошибки и оптимизировать код.
- Используйте `Assembly.GetName()` и рефлексию для отладки версий, но не применяйте рефлексию на «горячих» путях — она медленнее прямых вызовов.
- Подписывайте публикуемые библиотеки строгим именем (strong name) или Authenticode, чтобы гарантировать подлинность и версию.
- Learn IL with tools like `ildasm`, ILSpy, or sharplab.io — understanding IL helps you read errors and optimize.
- Use `Assembly.GetName()` and reflection to debug versions, but avoid reflection on hot paths — it is slower than direct calls.
- Sign published libraries with a strong name or Authenticode to guarantee authenticity and versioning.

#### Частые ошибки / Common Mistakes

- Думать, что `.dll` в .NET — это то же самое, что Win32 DLL → Помните, что .NET-сборка содержит IL + метаданные + манифест, а не машинный код; «нативность» появляется только в runtime через JIT.
- Считать, что GC освобождает ресурсы немедленно → GC работает по своему расписанию; для `IDisposable`-ресурсов (файлы, соединения) используйте `using`/`Dispose()`.
- Путать сборку с пространством имён → Сборка — это файл (.dll/.exe); пространство имён — логическая группировка типов внутри и между сборками.
- Thinking a .NET `.dll` is the same as a Win32 DLL → Remember a .NET assembly contains IL + metadata + a manifest, not machine code; it becomes "native" only at runtime via JIT.
- Believing the GC frees resources immediately → The GC runs on its own schedule; for `IDisposable` resources (files, connections) use `using`/`Dispose()`.
- Confusing an assembly with a namespace → An assembly is a file (.dll/.exe); a namespace is a logical grouping of types within and across assemblies.

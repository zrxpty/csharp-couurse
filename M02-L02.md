### Урок M02-L02: Примитивы: int, double, decimal, bool, char, string / Primitives: int, double, decimal, bool, char, string

**Время / Time:** 30 мин теория + 45 мин практика

#### Теория / Theory

В C# «примитивы» — это встроенные типы данных, из которых строятся все более сложные структуры. Технически спецификация языка называет их «простыми типами» (simple types), но в разговорной речи все говорят «примитивы». Выбор правильного типа важен: от него зависит точность вычислений, объём потребляемой памяти и даже корректность финансовых расчётов.

**Целочисленные типы.** Самый ходовой — `int` (32 бита, диапазон примерно от −2,1 до +2,1 миллиарда). Этого хватает для большинства счётчиков, индексов и идентификаторов. Когда миллиарда мало — берите `long` (64 бита, до ~9,2 квинтиллиона); литералы `long` помечаются суффиксом `L`: `long big = 9_000_000_000L;`. Для маленьких неотрицательных значений (цвета в RGB, байты файла) удобен `byte` (8 бит, 0–255). Есть ещё `short`, `sbyte`, `ushort`, `uint`, `ulong` — используйте их только когда действительно нужна экономия памяти, иначе читаемость страдает. Аналогия: целые типы — это коробки разного размера; выбирайте минимально достаточную, но не экономьте спичками там, где важна ясность.

**С плавающей точкой.** `double` — 64-битное число с двойной точностью (≈15–17 значащих цифр), значение по умолчанию для литералов с точкой. `float` — 32-битное (≈6–9 цифр), требует суффикса `f`: `float f = 3.14f;`. Аналогия: `double` и `float` хранят числа в двоичной системе, поэтому простые десятичные дроби вроде 0,1 в них не представимы точно — как 1/3 нельзя записать конечной десятичной дробью. Именно поэтому `0.1 + 0.2` в `double` даёт не ровно `0.3`, а `0.30000000000000004`.

**decimal для финансов.** `decimal` — 128-битный тип с высокой точностью (28–29 значащих цифр) и хранением в десятичной системе. Суффикс `m`: `decimal price = 19.99m;`. Главное правило: **деньги — всегда `decimal`**. Он исключает ошибки округления вроде «копейка потерялась». Платой за точность служит меньшая скорость и отсутствие поддержки ряда математических функций.

**bool.** Хранит только `true` или `false`. Логически это один бит, но в памяти занимает 1 байт. Никогда не сравнивайте `bool` с `true` через `==` — пишите просто `if (isActive)`.

**char.** Один Unicode-символ в кодировке UTF-16, заключается в одинарные кавычки: `'A'`, `'€'`. Не путайте со `string`.

**string.** Последовательность символов в двойных кавычках: `"Hello"`. Это ссылочный тип, но неизменяемый (immutable) — любая «модификация» создаёт новую строку. Для интерполяции — `$"..."`, для многострочных/raw-литералов — `"""..."""` (C# 11+).

**Суффиксы литералов.** `f` — float, `m` — decimal, `L` — long, `u` — uint, `UL` — ulong, `d` — double (неявный по умолчанию). Цифры можно разделять знаком `_` для читаемости: `1_000_000`.

**Когда decimal вместо double?** Всегда, когда важна точность в десятичной системе: деньги, проценты, налоги, курсы валют. `double` — для физических расчётов, координат, статистики, где микроскопические погрешности несущественны, а важна скорость.

#### Theory (EN)

In C#, "primitives" are the built-in data types from which everything else is composed. The language spec calls them "simple types," but everyone says "primitives." Choosing the right one matters: it affects precision, memory footprint, and even the correctness of financial calculations.

**Integer types.** The workhorse is `int` (32-bit, range roughly −2.1 billion to +2.1 billion) — enough for most counters, indices, and IDs. When a billion is too small, use `long` (64-bit, up to ~9.2 quintillion); `long` literals take the `L` suffix: `long big = 9_000_000_000L;`. For small non-negative values (RGB colors, file bytes) `byte` is handy (8-bit, 0–255). There are also `short`, `sbyte`, `ushort`, `uint`, `ulong` — reach for them only when memory savings genuinely matter, otherwise you sacrifice readability. Analogy: integer types are boxes of different sizes — pick the smallest sufficient one, but don't nickel-and-dime where clarity is at stake.

**Floating point.** `double` is the 64-bit double-precision type (~15–17 significant digits) and the default for literals containing a decimal point. `float` is 32-bit (~6–9 digits) and needs the `f` suffix: `float f = 3.14f;`. Analogy: `double` and `float` store numbers in binary, so simple decimals like 0.1 cannot be represented exactly — just as 1/3 has no finite decimal form. That's why `0.1 + 0.2` in `double` yields `0.30000000000000004`, not `0.3`.

**decimal for finance.** `decimal` is a 128-bit, high-precision type (28–29 significant digits) stored in base-10. Use the `m` suffix: `decimal price = 19.99m;`. The cardinal rule: **money is always `decimal`**. It eliminates rounding errors like the "lost penny." The trade-off is lower speed and sparser math-function support.

**bool.** Holds only `true` or `false`. Logically one bit, but it occupies one byte in memory. Never compare a `bool` to `true` with `==` — just write `if (isActive)`.

**char.** A single UTF-16 Unicode character in single quotes: `'A'`, `'€'`. Don't confuse it with `string`.

**string.** A sequence of characters in double quotes: `"Hello"`. It's a reference type but immutable — every "modification" creates a new string. Use `$"..."` for interpolation and `"""..."""` (C# 11+) for raw/multiline literals.

**Literal suffixes.** `f` — float, `m` — decimal, `L` — long, `u` — uint, `UL` — ulong, `d` — double (implicit default). Digits may be separated with `_` for readability: `1_000_000`.

**When decimal instead of double?** Whenever decimal-base precision matters: money, percentages, taxes, exchange rates. Use `double` for physics, coordinates, and statistics — where microscopic error is acceptable and speed matters.

#### Пример кода / Code Example

```csharp
// C# 12 / .NET 8 — примитивные типы / primitive types
// Top-level statements: точка входа без boilerplate / entry point without boilerplate

// --- Целочисленные / Integers ---
int count = 1_000_000;              // 32 бита / 32-bit
long big = 9_000_000_000L;          // суффикс L / L suffix
byte r = 255, g = 128, b = 0;       // 0..255, без знака / unsigned

// --- С плавающей точкой / Floating point ---
double approx = 0.1 + 0.2;          // НЕ равно ровно 0.3 / NOT exactly 0.3
float f = 3.14f;                    // суффикс f обязателен / f suffix required

// --- Финансы — только decimal / Money — decimal only ---
decimal price = 19.99m;             // суффикс m / m suffix
decimal total = price * 3;          // 59.97m — без потери копеек / no lost pennies

// --- bool / char / string ---
bool isActive = true;
char currency = '€';                // одинарные кавычки = символ / single quotes = char
string name = "Кофе / Coffee";      // двойные кавычки = строка / double quotes = string

// Интерполяция + raw string (C# 11+) / interpolation + raw string literal
string label = $"""{currency}{price:N2} — {name}""";
Console.WriteLine(label);           // €19.99 — Кофе / Coffee

// Покажем погрешность double / show double's imprecision
Console.WriteLine($"double 0.1+0.2 = {approx:R}");

// Pattern matching: выбор совета по сумме / pattern matching by amount
string advice = total switch
{
    > 100_000m => "Используйте decimal для крупных сумм / use decimal for large sums",
    < 0m       => "Отрицательный баланс / negative balance",
    _          => "Сумма в норме / amount is fine"
};
Console.WriteLine(advice);

// Демонстрация: почему НЕ double для денег / why NOT double for money
double  doubleMoney  = 0.1  + 0.1  + 0.1;    // 0.30000000000000004
decimal decimalMoney = 0.1m + 0.1m + 0.1m;   // ровно 0.3 / exactly 0.3
Console.WriteLine($"double:  {doubleMoney:R}");
Console.WriteLine($"decimal: {decimalMoney}");
```

#### Best Practices

- Деньги всегда считай в `decimal`; физику, графику и статистику — в `double`.
- Используй `int` по умолчанию для целых чисел; переходи на `long` только когда не хватает диапазона.
- Разделяй цифры знаком `_` для читаемости: `1_000_000`, `0.1m`.
- Не сравнивай `double`/`float` на точное равенство (`==`) — используй допуск (epsilon).
- Always do money in `decimal`; use `double` for physics, graphics, and statistics.
- Default to `int` for whole numbers; move to `long` only when the range is insufficient.
- Separate digits with `_` for readability: `1_000_000`, `0.1m`.
- Never compare `double`/`float` with `==` for exact equality — use an epsilon tolerance.

#### Частые ошибки / Common Mistakes

- Использование `double` для денег → теряются копейки из-за двоичного округления. Считай в `decimal`.
- Забыт суффикс `m` у денежного литерала `19.99` → компилятор трактует как `double`, ошибка типов. Пиши `19.99m`.
- `float f = 3.14;` → ошибка компиляции (литерал по умолчанию `double`). Добавь суффикс `f`: `3.14f`.
- `if (approx == 0.3)` для `double` → почти всегда `false`. Сравнивай через `Math.Abs(approx - 0.3) < 1e-9`.
- Путаница `char` (`'A'`) и `string` (`"A"`) → одинарные кавычки = символ, двойные = строка.
- Using `double` for money → pennies vanish due to binary rounding. Compute in `decimal`.
- Forgetting the `m` suffix on a money literal `19.99` → treated as `double`, type error. Write `19.99m`.
- `float f = 3.14;` → compile error (literal defaults to `double`). Add the `f` suffix: `3.14f`.
- `if (approx == 0.3)` on a `double` → almost always `false`. Compare with `Math.Abs(approx - 0.3) < 1e-9`.
- Mixing up `char` (`'A'`) and `string` (`"A"`) → single quotes = char, double quotes = string.

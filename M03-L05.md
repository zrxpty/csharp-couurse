### Урок M03-L05: Объявление методов, сигнатура, возвращаемые значения / Declaring methods, signature, return values

**Время / Time:** 30 мин теория + 45 мин практика

#### Теория / Theory

Метод — это именованный блок кода, выполняющий одну задачу. Методы превращают большую программу в набор понятных шагов, которые можно вызывать многократно. Аналогия: метод как рецепт в кулинарной книге — у него есть название, список ингредиентов (параметры) и результат (возврат). Метод должен делать одну вещь и делать её хорошо; название должно говорить, **что** он делает, а не **как**.

**Анатомия объявления.** Любой метод в C# состоит из пяти частей:
```
модификатор_доступа  тип_возврата  Имя(параметры)  {  тело  }
public               int           Add(int a, int b)   => a + b;
```
1. **Модификатор доступа** (`public`, `private`, `protected`, `internal`) — кто может вызывать метод. По умолчанию (если не указан) для классов действует `private`. Правило: начинайте с `private` и открывайте (`public`) только когда это действительно нужно остальному коду.
2. **Тип возврата** — какой результат метод отдаёт. Либо конкретный тип (`int`, `string`, `Calculator`), либо `void` («ничего не возвращает»). Аналогия: у команды «выключи свет» нет результата, а у команды «сколько сейчас времени?» — есть.
3. **Имя** — идентификатор, по которому метод вызывают.
4. **Параметры** — входные данные в скобках, каждый со своим типом. Могут отсутствовать: `()` — тогда метод работает «без ингредиентов».
5. **Тело** — код между `{ ... }`. Для коротких методов тело можно записать выражением через `=>` (expression-bodied method): `public int Add(int a, int b) => a + b;`.

**static vs instance.** Метод без слова `static` — *экземплярный* (instance): он работает с данными конкретного объекта и вызывается через переменную: `calc.Add(...)`. Метод со словом `static` принадлежит самому типу, а не объекту, и вызывается через имя класса: `Math.Sqrt(...)`, `Calculator.Multiply(...)`. Аналогия: instance-метод — это «поведение конкретной собаки» (лай), а static-метод — «универсальная функция про собак вообще» (например, сравнение пород). Если методу не нужны поля объекта — делайте его `static`.

**void vs возврат значения.** Метод с типом возврата, отличным от `void`, **обязан** вернуть значение через `return` на каждом пути выполнения — иначе компилятор выдаст ошибку. Метод `void` тоже может содержать `return;` (без значения) — для раннего выхода. Не возвращайте результат «через out-параметр», когда можно вернуть его обычным `return`, — это усложняет чтение.

**return в нескольких местах.** Внутри одного метода `return` может встречаться несколько раз — это нормально и часто повышает читаемость. Классический пример — валидация: сначала проверяем граничные случаи и выходим, затем идём к основному вычислению. Однако не стоит возвращать из одного метода значения разных типов или раскидывать десятки `return` по глубоко вложенным веткам — единая точка выхода (single exit) иногда понятнее.

**Именование методов.** В C# принято: **PascalCase** (`CalculateTotal`, не `calculateTotal`), имя — **глагол** или глагольная фраза, описывающая действие (`SendEmail`, `TryParse`). Имя должно быть самодокументируемым: `GetUserById(int id)` лучше, чем `GetData(int x)`. Для методов-предикатов (возвращают `bool`) хорош стиль `Is...`/`Has...`/`Can...`: `IsActive`, `HasPermission`, `CanConnect`. Старайтесь, чтобы имя говорило «что», а не «как»: `CalculateTax` — хорошо, `LoopOverItemsAndSum` — плохо.

#### Theory (EN)

A method is a named block of code that performs one task. Methods turn a large program into a set of understandable steps you can call repeatedly. Analogy: a method is like a recipe in a cookbook — it has a name, a list of ingredients (parameters), and a result (return value). A method should do one thing and do it well; its name should describe **what** it does, not **how**.

**Anatomy of a declaration.** Every C# method has five parts:
```
access_modifier  return_type  Name(parameters)  {  body  }
public           int          Add(int a, int b)   => a + b;
```
1. **Access modifier** (`public`, `private`, `protected`, `internal`) — who may call the method. If omitted inside a class, it defaults to `private`. Rule of thumb: start with `private` and open up (`public`) only when other code genuinely needs it.
2. **Return type** — what the method yields. Either a concrete type (`int`, `string`, `Calculator`) or `void` ("returns nothing"). Analogy: the command "turn off the light" has no result, but "what time is it?" does.
3. **Name** — the identifier you call the method by.
4. **Parameters** — input data in parentheses, each with its own type. May be empty: `()` means "no ingredients."
5. **Body** — the code between `{ ... }`. For short methods the body can be written as an expression via `=>` (expression-bodied method): `public int Add(int a, int b) => a + b;`.

**static vs instance.** A method without the `static` keyword is an *instance* method: it works with the data of a specific object and is called through a variable: `calc.Add(...)`. A `static` method belongs to the type itself, not to any object, and is called through the class name: `Math.Sqrt(...)`, `Calculator.Multiply(...)`. Analogy: an instance method is "behavior of a particular dog" (bark), while a static method is "a general-purpose function about dogs" (e.g., comparing breeds). If a method doesn't need any object fields, make it `static`.

**void vs returning a value.** A method whose return type is anything other than `void` **must** return a value via `return` on every execution path — otherwise the compiler errors out. A `void` method may still use `return;` (no value) for an early exit. Don't smuggle results out through `out` parameters when a plain `return` would do — it hurts readability.

**return in multiple places.** A single method may contain several `return` statements — this is normal and often improves clarity. A classic example is validation: check edge cases first and bail out, then proceed to the main computation. That said, don't return values of different types from one method, and don't scatter dozens of `return`s across deeply nested branches — a single exit point is sometimes clearer.

**Naming methods.** The C# convention is **PascalCase** (`CalculateTotal`, not `calculateTotal`) and the name should be a **verb** or verb phrase describing the action (`SendEmail`, `TryParse`). The name should be self-documenting: `GetUserById(int id)` beats `GetData(int x)`. For predicate methods (returning `bool`) the `Is...`/`Has...`/`Can...` style reads well: `IsActive`, `HasPermission`, `CanConnect`. Aim for the name to say "what," not "how": `CalculateTax` — good; `LoopOverItemsAndSum` — bad.

#### Пример кода / Code Example

```csharp
// C# 12 / .NET 8 — объявление методов / declaring methods
// Top-level statements: точка входа без boilerplate / entry point without boilerplate

var calc = new Calculator();                 // instance-методы вызываем через объект / instance methods via object
calc.PrintResult(calc.Add(2, 3));            // Add возвращает int / Add returns int
Console.WriteLine(Calculator.Multiply(4, 5));// static вызывается через имя класса / static via class name
Console.WriteLine(calc.Classify(75));        // несколько return / multiple returns
Console.WriteLine(Calculator.Describe(null));// pattern matching + static / pattern matching + static

// --- Объявление класса с методами / class with methods ---
// Анатомия метода: [модификатор] [тип возврата] Имя([параметры]) { тело }
// Method anatomy: [access modifier] [return type] Name([parameters]) { body }

public class Calculator
{
    // Экземплярный метод, возвращает int, expression-bodied / instance method, returns int
    // Доступ: public — виден снаружи класса / access: public — visible outside
    public int Add(int a, int b) => a + b;

    // static: не требует объекта, принадлежит типу / static: needs no object, belongs to the type
    public static int Multiply(int a, int b) => a * b;

    // void: ничего не возвращает, только побочный эффект / void: returns nothing, side effect only
    public void PrintResult(int value)
    {
        Console.WriteLine($"Result: {value}");
        // здесь return; необязателен — метод завершается сам / return; optional here
    }

    // Несколько return — ранние выходы повышают читаемость / multiple returns: early exits aid clarity
    public string Classify(int score)
    {
        if (score < 0)  return "Negative / Отрицательно";   // ранний выход / early exit
        if (score == 0) return "Zero / Ноль";
        if (score < 60) return "Fail / Не сдан";
        return "Pass / Сдан";                               // основной возврат / main return
    }

    // static + pattern matching (C# 8+) / static + pattern matching
    // Имя-предикат не подходит здесь (возвращаем string), но имя глагольное и ясное
    // Predicate-style name doesn't fit (we return string), but the verb name is clear
    public static string Describe(int? value) => value switch
    {
        null => "No value / Нет значения",
        0    => "Zero / Ноль",
        < 0  => "Negative / Отрицательно",
        > 0  => "Positive / Положительно",
    };
}
```

#### Best Practices

- Начинай метод с `private`; открывай `public` только когда это нужно остальному коду.
- Делай метод `static`, если он не обращается к полям объекта, — это яснее и чуть быстрее.
- Имя метода — глагол в **PascalCase**, самодокументирующий: `GetUserById`, а не `GetData`.
- Один метод — одна задача; не возвращай значения разных типов и не плодите десятки `return` в глубокой вложенности.
- Результат возвращай через `return`, а не через `out`, когда это уместно.
- Start a method as `private`; make it `public` only when other code truly needs it.
- Make a method `static` when it touches no instance fields — clearer and marginally faster.
- Name methods with verbs in **PascalCase**, self-documenting: `GetUserById`, not `GetData`.
- One method, one job; never return different types and avoid dozens of nested `return`s.
- Return results via `return`, not `out`, whenever it fits.

#### Частые ошибки / Common Mistakes

- Забыт `return` на каком-то пути выполнения (метод не `void`) → компилятор выдаст CS0161. Проследи, чтобы каждая ветка возвращала значение.
- Имя метода — существительное (`Data`, `Calculation`) → переименуй в глагол: `GetData`, `PerformCalculation`.
- `public` везде «на всякий случай» → инкапсуляция страдает. Начинай с `private`.
- Вызов instance-метода как `Calculator.Add(2,3)` (без объекта) → CS0120. Либо создай объект, либо сделай метод `static`.
- Метод `void` пытается вернуть значение (`return 5;`) → CS0126. Для `void` — только `return;` или вовсе без `return`.
- Загрязнение параметров `out`-аргументами там, где можно вернуть значение → верни результат через `return`, оставь `out` для `Try...`-паттерна.
- Missing `return` on some path (non-`void` method) → compiler raises CS0161. Make every branch return a value.
- Method named with a noun (`Data`, `Calculation`) → rename to a verb: `GetData`, `PerformCalculation`.
- `public` everywhere "just in case" → encapsulation suffers. Start with `private`.
- Calling an instance method as `Calculator.Add(2,3)` (no object) → CS0120. Either create an object or make the method `static`.
- A `void` method trying to return a value (`return 5;`) → CS0126. For `void`, use `return;` or omit `return`.
- Polluting parameters with `out` args where a return value would do → return via `return`; reserve `out` for the `Try...` pattern.

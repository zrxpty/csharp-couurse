## Постановка на русском / Russian statement

#### Контекст и мотивация

Вы присоединились к команде микросервиса `Shop.Shipping`, который рассчитывает стоимость доставки заказа. Логика калькулятора нетривиальна: бесплатная доставка при сумме корзины выше порога, наценка за экспресс-доставку, зонный множитель для международных заказов, надбавка за хрупкие товары и градации по весу. Команда давно пишет unit-тесты на xUnit, но никто не знает, какая часть бизнес-логики реально проверена. На последнем ретро продакт-менеджер пожаловался, что в продакшен дважды прорвался баг с неправильным расчётом хрупкого груза для международной зоны — то есть в «слепой зоне» тестов.

Руководитель разработки попросил вас настроить инфраструктуру покрытия: подключить coverlet, научиться генерировать HTML-отчёты и сформулировать политику порогов по слоям. Важно: команда уже обожглась на прошлом проекте, где гнались за 100% line coverage и писали пустые тесты без assert'ов. Поэтому ваша задача — не «выполнить KPI», а превратить coverage в осмысленный сигнал для ревью: где тестов нет совсем, где ветви проверены не со всех сторон, где в отчёт попал автогенерированный шум, который надо исключить. Вы должны объяснить коллегам разницу между line и branch coverage на конкретном примере и показать, как один непокрытый `if` может прятать серьёзный баг.

По итогам ДЗ у вас должен быть рабочий репозиторий с тестовым проектом, настроенным coverlet, скриптом генерации HTML-отчёта, файлом `coverlet.runsettings` с порогами и краткой политикой coverage для команды. Параллельно вы допишете тесты так, чтобы критичные ветви калькулятора были покрыты, но без фанатизма — защитные `throw` останутся непокрытыми намеренно, и вы обоснуете это решение.

#### Что нужно сделать (пошагово)

1. **Создайте структуру решения.** В папке `src/Shop.Shipping` создайте библиотеку классов `Shop.Shipping.csproj` (target framework `net8.0`). В папке `tests/Shop.Shipping.Tests` создайте xUnit-проект `Shop.Shipping.Tests.csproj`. Решение `Shop.Shipping.sln` должно ссылаться на оба проекта. Используйте `dotnet new sln`, `dotnet new classlib`, `dotnet new xunit`, `dotnet sln add`.

2. **Реализуйте калькулятор.** В `ShippingCostCalculator.cs` опишите класс `ShippingCostCalculator` с методом `Calculate(Order order)`, где `Order` — рекорд с полями `decimal Subtotal`, `bool IsExpress`, `ShippingZone Zone`, `bool IsFragile`, `decimal WeightKg`. `ShippingZone` — перечисление `Domestic`, `Eu`, `International`. Используйте C# 12: pattern matching с `when`, collection expressions там, где уместно (например, для списка надбавок), raw-string литералы для сообщений об ошибках. Включите как минимум пять ветвлений: порог бесплатной доставки, экспресс-надбавка, зонный множитель, хрупкая надбавка, градация по весу. Добавьте защитные `throw new ArgumentOutOfRangeException` для невалидных входов.

3. **Подключите coverlet.** В тестовый проект добавьте NuGet-пакет `coverlet.collector` через `dotnet add package coverlet.collector`. Убедитесь, что `dotnet test` по-прежнему проходит. Запустите `dotnet test --collect:"XPlat Code Coverage"` и найдите сгенерированный XML-файл в `tests/Shop.Shipping.Tests/TestResults/<guid>/coverage.cobertura.xml`. Откройте его и найдите атрибуты `line-rate` и `branch-rate`.

4. **Установите ReportGenerator как global tool.** Выполните `dotnet tool install -g dotnet-reportgenerator-globaltool`. Сгенерируйте HTML-отчёт: `reportgenerator -reports:"**/coverage.cobertura.xml" -targetdir:"coverage-report" -reporttypes:"Html;Cobertura"`. Откройте `coverage-report/index.htm` в браузере. Найдите класс `ShippingCostCalculator` и посмотрите, какие строки и ветви подсвечены красным.

5. **Проанализируйте разницу line vs branch.** Запишите в `NOTES.md`: текущий `line-rate`, текущий `branch-rate`, список непокрытых ветвей. Найдите минимум одну ветвь, у которой line coverage = 100%, но branch coverage < 100% — это и есть «слепая зона» урока. Объясните в `NOTES.md`, почему так происходит.

6. **Допишите тесты осмысленно.** Покройте критичные для бизнеса ветви: бесплатная доставка выше порога, экспресс для международной зоны, хрупкий груз для EU. Не пишите пустые тесты — каждый тест должен содержать assert на конкретное ожидаемое число. Не покрывайте защитные `throw` ради процента; в `NOTES.md` обоснуйте, почему эти ветви оставлены непокрытыми намеренно (защитный код, paths that can never occur).

7. **Исключите шум.** Добавьте в `ShippingCostCalculator` автогенерированный-по-видимому класс `GeneratedMapper` с атрибутом `[System.Diagnostics.CodeAnalysis.ExcludeFromCodeCoverage]`. Настройте в `coverlet.runsettings` фильтр исключения по атрибуту и по маске `*Generated*`. Перезапустите сборку и убедитесь, что класс исчез из отчёта.

8. **Настройте пороги по слоям.** В `coverlet.runsettings` задайте threshold для сборки `Shop.Shipping`: `line` 80%, `branch` 70%. Для тестового проекта — без порога. Запустите `dotnet test --collect:"XPlat Code Coverage" --settings coverlet.runsettings` и убедитесь, что сборка падает, если порог не достигнут (или проходит, если вы дописали тесты правильно).

9. **Опишите CI-сценарий.** В `ci-coverage.md` пропишите шаги: `dotnet test --collect`, `reportgenerator`, публикация артефакта `coverage-report/` и комментарий в PR с дельтой покрытия относительно базовой ветки. Укажите, что merge блокируется при падении покрытия, а не при недостижении абсолюта.

#### Требования к решению

Решение должно компилироваться под .NET 8 (целевой фреймворк `net8.0`), использовать возможности C# 12 там, где они уместны: pattern matching с `when` для зон, collection expressions для формирования списка надбавок, raw-string литералы для многострочных сообщений об ошибках, `file-scoped namespaces`, `init`-свойства у `Order`. Тесты — на xUnit, с `[Fact]` и `[Theory]`/`[InlineData]`, без mock-фреймворков (калькулятор — чистая функция). Каждый тест обязан содержать содержательный `Assert.Equal` с ожидаемой суммой, вычисленной вручную.

coverlet должен быть подключён именно через `coverlet.collector` (а не `coverlet.msbuild`), чтобы команда `dotnet test --collect:"XPlat Code Coverage"` работала кроссплатформенно. ReportGenerator — как global tool. HTML-отчёт должен реально генерироваться и открываться. В `coverlet.runsettings` должны быть заданы и пороги, и фильтры исключения. Файл `NOTES.md` должен содержать числовые метрики до и после дописывания тестов, объяснение разницы line vs branch и обоснование оставленных непокрытыми защитных ветвей. Файл `ci-coverage.md` должен описывать конвейер с публикацией артефакта и комментарием дельты в PR. Код должен быть отформатирован и читаем, без `// TODO` и заглушек.

#### Тонкости и подводные камни

- **line ≠ branch.** Даже если обе строки `if` и `else` выполнились в *разных* тестах, branch coverage считает ветвь покрытой только тогда, когда проверены все пути решения. Сложный `if` с `&&` или `||` может иметь 100% строк и 50% веток. Включайте branch-метрику в отчёты по умолчанию и смотрите на неё чаще, чем на line.
- **Путь к XML нестабилен.** coverlet складывает результаты в `TestResults/<guid>/coverage.cobertura.xml`. GUID меняется при каждом прогоне. Для ReportGenerator используйте glob `**/coverage.cobertura.xml`, а не хардкод пути.
- **`XPlat Code Coverage` vs `Code Coverage`.** Первая — кроссплатформенный формат coverlet (OpenCover/Cobertura), работает на Linux/macOS/Windows. Вторая — встроенный коллектор Visual Studio, только Windows. В CI и на маках используйте именно `XPlat Code Coverage`.
- **Исключение через атрибут и через фильтр.** `ExcludeFromCodeCoverage` работает точечно для класса/метода. Фильтры в `coverlet.runsettings` (`-:*.Generated*`) — для массовых исключений по маске. Комбинируйте оба: атрибут — для единичных защитных классов, фильтр — для сгенерированных папок.
- **Пороги без контекста вредят.** Единый абсолютный порог 80% на всё решение заставит исключать UI-адаптеры вручную или писать пустые тесты. Ставьте пороги по сборкам: core-логика — жёстко, адаптеры — мягко, сгенерированное — исключено.
- **coverage не гарантирует корректность.** Тест, который вызывает метод и игнорирует результат, «покроет» строку, но баг останется. Дополняйте мутационным тестированием и code review.
- **100% — почти всегда плохо.** Защитные `throw new NotImplementedException()` для путей, которые никогда не произойдут, автогенерированный код, source generators — гнаться за ними значит раздувать maintenance без выгоды.

- Вспомните аналогию урока про дорожную сеть: line — «проехал по улице», branch — «свернул и налево, и направо». Где в калькуляторе перекрёсток, который вы всегда проезжаете только прямо?

#### Эталонное решение (разбор)

```csharp
// C# 12 / .NET 8 — Shop.Shipping / ShippingCostCalculator.cs
// Калькулятор стоимости доставки с осмысленными ветвлениями для демонстрации coverage
// Shipping cost calculator with meaningful branches to demonstrate coverage

namespace Shop.Shipping;

using System.Diagnostics.CodeAnalysis;

public enum ShippingZone { Domestic, Eu, International }

public sealed record Order(
    decimal Subtotal,
    bool IsExpress,
    ShippingZone Zone,
    bool IsFragile,
    decimal WeightKg);

public sealed class ShippingCostCalculator
{
    private const decimal FreeShippingThreshold = 50m;   // Порог бесплатной доставки / Free shipping threshold
    private const decimal ExpressSurcharge = 12.5m;       // Наценка за экспресс / Express surcharge
    private const decimal FragileSurcharge = 9.0m;        // Надбавка за хрупкий груз / Fragile surcharge
    private const decimal MaxWeightKg = 30m;              // Лимит веса / Weight limit

    public decimal Calculate(Order order)
    {
        // Защитные проверки — НЕ покрываем ради процента (defensive code, paths that can't occur)
        // Guard checks — NOT covered for the percentage's sake
        if (order.Subtotal < 0)
            throw new ArgumentOutOfRangeException(nameof(order.Subtotal),
                "Subtotal cannot be negative");
        if (order.WeightKg is <= 0 or > MaxWeightKg)
            throw new ArgumentOutOfRangeException(nameof(order.WeightKg),
                """
                Weight must be within (0; 30] kg.
                Invalid weight breaks carrier contracts.
                """);
        if (order.Zone is not (ShippingZone.Domestic or ShippingZone.Eu or ShippingZone.International))
            throw new ArgumentOutOfRangeException(nameof(order.Zone), "Unknown zone");

        // 1. Порог бесплатной доставки — критичная ветвь, оба пути должны быть в тестах
        // 1. Free-shipping threshold — critical branch, both paths must be tested
        decimal baseCost = order.Subtotal >= FreeShippingThreshold
            ? 0m
            : 5.0m;

        // 2. Зонный множитель через pattern matching с when
        // 2. Zone multiplier via pattern matching with when
        decimal zoneMultiplier = order.Zone switch
        {
            ShippingZone.Domestic => 1.0m,
            ShippingZone.Eu => 1.2m,
            ShippingZone.International => 1.5m,
            _ => 1.0m
        };

        // 3. Градация по весу — ещё одна ветвь, часто «слепая зона»
        // 3. Weight tier — another branch, often a blind spot
        decimal weightFee = order.WeightKg switch
        {
            < 1m => 0m,
            < 5m => 2.0m,
            < 15m => 5.0m,
            _ => 10.0m
        };

        // 4. Надбавки собираются через collection expression — C# 12
        // 4. Surcharges assembled via collection expression — C# 12
        decimal[] surcharges = [
            order.IsExpress ? ExpressSurcharge : 0m,
            order.IsFragile ? FragileSurcharge : 0m,
            weightFee
        ];

        decimal surchargeTotal = surcharges.Sum();

        // 5. Итог: базовая стоимость + надбавки, умноженные на зонный множитель
        // 5. Total: base + surcharges, multiplied by zone factor
        decimal raw = (baseCost + surchargeTotal) * zoneMultiplier;

        return Math.Round(raw, 2, MidpointRounding.AwayFromZero);
    }
}

// Симуляция автогенерированного кода — исключаем из coverage
// Simulated generated code — excluded from coverage
[ExcludeFromCodeCoverage]
public sealed class GeneratedMapper
{
    public string Map(Order o) => $"GEN::{o.Subtotal}::{o.Zone}";
}
```

```csharp
// C# 12 / .NET 8 — Shop.Shipping.Tests / ShippingCostCalculatorTests.cs
using Shop.Shipping;
using Xunit;

namespace Shop.Shipping.Tests;

public sealed class ShippingCostCalculatorTests
{
    private readonly ShippingCostCalculator _calc = new();

    [Fact]
    public void Calculate_AboveFreeShippingThreshold_Domestic_NoSurcharges_ReturnsZero()
    {
        // subtotal=60 >= 50 → base=0; domestic → x1; без экспресса и хрупкого → 0
        // subtotal=60 >= 50 → base=0; domestic → x1; no express/fragile → 0
        var order = new Order(Subtotal: 60m, IsExpress: false, Zone: ShippingZone.Domestic,
                              IsFragile: false, WeightKg: 0.5m);
        Assert.Equal(0m, _calc.Calculate(order));
    }

    [Fact]
    public void Calculate_BelowThreshold_Domestic_Express_Fragile_ReturnsRoundedTotal()
    {
        // subtotal=40 < 50 → base=5; weight 0.5kg → weightFee=0; express=12.5; fragile=9
        // surcharges = [12.5, 9, 0] = 21.5; raw = (5 + 21.5) * 1.0 = 26.5
        var order = new Order(Subtotal: 40m, IsExpress: true, Zone: ShippingZone.Domestic,
                              IsFragile: true, WeightKg: 0.5m);
        Assert.Equal(26.5m, _calc.Calculate(order));
    }

    [Fact]
    public void Calculate_InternationalExpressFragileHeavy_AppliesZoneMultiplier()
    {
        // subtotal=100 >= 50 → base=0; international → x1.5; weight 20kg → weightFee=10; express+fragile
        // surcharges = [12.5, 9, 10] = 31.5; raw = (0 + 31.5) * 1.5 = 47.25
        var order = new Order(Subtotal: 100m, IsExpress: true, Zone: ShippingZone.International,
                              IsFragile: true, WeightKg: 20m);
        Assert.Equal(47.25m, _calc.Calculate(order));
    }

    [Theory]
    [InlineData(0.5, 2.0)]   // tier 1–5kg → 2.0
    [InlineData(10, 5.0)]    // tier 5–15kg → 5.0
    [InlineData(25, 10.0)]   // tier >15kg → 10.0
    public void Calculate_WeightTiers_ApplyCorrectFee(decimal weight, decimal expectedFee)
    {
        // base=5 (subtotal<50), domestic, no express/fragile → raw = (5 + expectedFee) * 1.0
        var order = new Order(Subtotal: 10m, IsExpress: false, Zone: ShippingZone.Domestic,
                              IsFragile: false, WeightKg: weight);
        Assert.Equal(5m + expectedFee, _calc.Calculate(order));
    }
}
```

Разбор по строкам. Класс `Order` — `sealed record` с позиционными параметрами: value semantics, immutability, лаконичность — идиоматично для .NET 8. Константы `FreeShippingThreshold`, `ExpressSurcharge` и др. вынесены в `private const` — это и читаемость, и готовые «магические числа» для тестов. Защитные проверки в начале метода — это *defensive code* для путей, которые «не могут произойти»: урок явно говорит не гонять их ради 100% coverage, поэтому в тестах их нет, и в `NOTES.md` это обосновано. Raw-string литерал `"""..."""` — C# 12, удобен для многострочных сообщений об ошибках без экранирования кавычек.

Первое ветвление `order.Subtotal >= FreeShippingThreshold` — тернарный оператор с двумя путями; оба покрыты тестами (`Calculate_Above...` и `Calculate_Below...`), иначе branch coverage упал бы до 50%. Зонный множитель через `switch` с pattern matching — три臂вых пути плюс `_`; тест на `International` + `Domestic` + (косвенно) `Eu` покрывают основные ветви, а `_` остаётся defensive. Градация по весу — классический «слепая зона»: четыре臂а, покрыты через `[Theory]` с тремя `InlineData` плюс неявно tier `< 1m` в первом тесте. Если бы мы покрыли только line, все строки выполнились бы, но branch остался бы неполным — ровно та иллюстрация, которую требует урок.

Collection expression `[...]` для надбавок — новинка C# 12, читается чище `new[] { ... }`. Каждая надбавка — отдельная ветвь (`order.IsExpress ? ...`), и тесты intentionally варьируют эти флаги, чтобы покрыть обе臂а каждого тернарника. Финальный `Math.Round(..., MidpointRounding.AwayFromZero)` — бизнес-правило округления, которое в продакшене часто становится источником багов; тест на `47.25` фиксирует поведение. Класс `GeneratedMapper` помечен `[ExcludeFromCodeCoverage]` — симуляция автогенерированного кода, который должен исчезнуть из отчёта; фильтр `coverlet.runsettings` дублирует исключение по маске `*Generated*`. Вместе это демонстрирует две стратегии исключения шума из урока: точечный атрибут и массовый фильтр. Тесты используют `[Fact]` для конкретных сценариев и `[Theory]/[InlineData]` для параметризованной градации веса — стандартная связка xUnit, coverlet соберёт по ним все три метрики. Никаких mock-фреймворков: калькулятор — чистая функция, что упрощает и тесты, и интерпретацию coverage.

#### Pitfalls

- **line ≠ branch.** Even if both the `if` and `else` lines ran in *different* tests, branch coverage counts a branch covered only when every decision path has been taken. A complex `if` with `&&` or `||` can have 100% lines and 50% branches. Enable the branch metric by default and look at it more often than line coverage.
- **The XML path is unstable.** coverlet drops results under `TestResults/<guid>/coverage.cobertura.xml`. The GUID changes every run. Use the glob `**/coverage.cobertura.xml` for ReportGenerator, not a hardcoded path.
- **`XPlat Code Coverage` vs `Code Coverage`.** The first is the cross-platform coverlet format (OpenCover/Cobertura) that works on Linux/macOS/Windows. The second is the built-in Visual Studio collector, Windows-only. In CI and on macOS use `XPlat Code Coverage`.
- **Attribute vs filter exclusion.** `ExcludeFromCodeCoverage` works pointwise for a class/method. Filters in `coverlet.runsettings` (`-:*.Generated*`) are for mass exclusions by mask. Combine both: attribute for single defensive classes, filter for generated folders.
- **Thresholds without context harm.** A single absolute 80% threshold across the whole solution forces manual exclusions of UI adapters or hollow tests. Set thresholds per assembly: core logic — strict, adapters — lenient, generated — excluded.
- **Coverage does not guarantee correctness.** A test that calls a method and ignores the result "covers" the line, but the bug stays. Supplement with mutation testing and code review.
- **100% is almost always bad.** Defensive `throw new NotImplementedException()` for paths that can never occur, autogenerated code, source generators — chasing them inflates maintenance with no payoff.

```csharp
// C# 12 / .NET 8 — Shop.Shipping / ShippingCostCalculator.cs
// Shipping cost calculator with meaningful branches to demonstrate coverage

namespace Shop.Shipping;

using System.Diagnostics.CodeAnalysis;

public enum ShippingZone { Domestic, Eu, International }

public sealed record Order(
    decimal Subtotal,
    bool IsExpress,
    ShippingZone Zone,
    bool IsFragile,
    decimal WeightKg);

public sealed class ShippingCostCalculator
{
    private const decimal FreeShippingThreshold = 50m;   // Free shipping threshold
    private const decimal ExpressSurcharge = 12.5m;       // Express surcharge
    private const decimal FragileSurcharge = 9.0m;        // Fragile surcharge
    private const decimal MaxWeightKg = 30m;              // Weight limit

    public decimal Calculate(Order order)
    {
        // Guard checks — NOT covered for the percentage's sake (defensive code)
        if (order.Subtotal < 0)
            throw new ArgumentOutOfRangeException(nameof(order.Subtotal),
                "Subtotal cannot be negative");
        if (order.WeightKg is <= 0 or > MaxWeightKg)
            throw new ArgumentOutOfRangeException(nameof(order.WeightKg),
                """
                Weight must be within (0; 30] kg.
                Invalid weight breaks carrier contracts.
                """);
        if (order.Zone is not (ShippingZone.Domestic or ShippingZone.Eu or ShippingZone.International))
            throw new ArgumentOutOfRangeException(nameof(order.Zone), "Unknown zone");

        // 1. Free-shipping threshold — critical branch, both paths must be tested
        decimal baseCost = order.Subtotal >= FreeShippingThreshold
            ? 0m
            : 5.0m;

        // 2. Zone multiplier via pattern matching
        decimal zoneMultiplier = order.Zone switch
        {
            ShippingZone.Domestic => 1.0m,
            ShippingZone.Eu => 1.2m,
            ShippingZone.International => 1.5m,
            _ => 1.0m
        };

        // 3. Weight tier — another branch, often a blind spot
        decimal weightFee = order.WeightKg switch
        {
            < 1m => 0m,
            < 5m => 2.0m,
            < 15m => 5.0m,
            _ => 10.0m
        };

        // 4. Surcharges assembled via collection expression — C# 12
        decimal[] surcharges = [
            order.IsExpress ? ExpressSurcharge : 0m,
            order.IsFragile ? FragileSurcharge : 0m,
            weightFee
        ];

        decimal surchargeTotal = surcharges.Sum();

        // 5. Total: base + surcharges, multiplied by zone factor
        decimal raw = (baseCost + surchargeTotal) * zoneMultiplier;

        return Math.Round(raw, 2, MidpointRounding.AwayFromZero);
    }
}

// Simulated generated code — excluded from coverage
[ExcludeFromCodeCoverage]
public sealed class GeneratedMapper
{
    public string Map(Order o) => $"GEN::{o.Subtotal}::{o.Zone}";
}
```

```csharp
// C# 12 / .NET 8 — Shop.Shipping.Tests / ShippingCostCalculatorTests.cs
using Shop.Shipping;
using Xunit;

namespace Shop.Shipping.Tests;

public sealed class ShippingCostCalculatorTests
{
    private readonly ShippingCostCalculator _calc = new();

    [Fact]
    public void Calculate_AboveFreeShippingThreshold_Domestic_NoSurcharges_ReturnsZero()
    {
        // subtotal=60 >= 50 → base=0; domestic → x1; no express/fragile → 0
        var order = new Order(Subtotal: 60m, IsExpress: false, Zone: ShippingZone.Domestic,
                              IsFragile: false, WeightKg: 0.5m);
        Assert.Equal(0m, _calc.Calculate(order));
    }

    [Fact]
    public void Calculate_BelowThreshold_Domestic_Express_Fragile_ReturnsRoundedTotal()
    {
        // subtotal=40 < 50 → base=5; weight 0.5kg → weightFee=0; express=12.5; fragile=9
        // surcharges = [12.5, 9, 0] = 21.5; raw = (5 + 21.5) * 1.0 = 26.5
        var order = new Order(Subtotal: 40m, IsExpress: true, Zone: ShippingZone.Domestic,
                              IsFragile: true, WeightKg: 0.5m);
        Assert.Equal(26.5m, _calc.Calculate(order));
    }

    [Fact]
    public void Calculate_InternationalExpressFragileHeavy_AppliesZoneMultiplier()
    {
        // subtotal=100 >= 50 → base=0; international → x1.5; weight 20kg → weightFee=10; express+fragile
        // surcharges = [12.5, 9, 10] = 31.5; raw = (0 + 31.5) * 1.5 = 47.25
        var order = new Order(Subtotal: 100m, IsExpress: true, Zone: ShippingZone.International,
                              IsFragile: true, WeightKg: 20m);
        Assert.Equal(47.25m, _calc.Calculate(order));
    }

    [Theory]
    [InlineData(0.5, 2.0)]   // tier 1–5kg → 2.0
    [InlineData(10, 5.0)]    // tier 5–15kg → 5.0
    [InlineData(25, 10.0)]   // tier >15kg → 10.0
    public void Calculate_WeightTiers_ApplyCorrectFee(decimal weight, decimal expectedFee)
    {
        // base=5 (subtotal<50), domestic, no express/fragile → raw = (5 + expectedFee) * 1.0
        var order = new Order(Subtotal: 10m, IsExpress: false, Zone: ShippingZone.Domestic,
                              IsFragile: false, WeightKg: weight);
        Assert.Equal(5m + expectedFee, _calc.Calculate(order));
    }
}
```

Line-by-line walk-through. The `Order` type is a `sealed record` with positional parameters: value semantics, immutability, and conciseness — idiomatic for .NET 8. The constants `FreeShippingThreshold`, `ExpressSurcharge` and friends are `private const`: readability plus named "magic numbers" that tests can rely on. The guard checks at the top of `Calculate` are *defensive code* for paths that "cannot happen": the lesson explicitly says not to chase them for 100% coverage, so the tests do not exercise them and `NOTES.md` justifies that. The raw-string literal `"""..."""` is a C# 12 feature, handy for multi-line error messages without escaping quotes.

The first branch `order.Subtotal >= FreeShippingThreshold` is a ternary with two paths; both are covered by tests (`Calculate_Above...` and `Calculate_Below...`), otherwise branch coverage would drop to 50%. The zone multiplier via `switch` with pattern matching has three real arms plus `_`; tests for `International` + `Domestic` + (indirectly) `Eu` cover the main branches, while `_` stays defensive. The weight tier is a classic "blind spot": four arms, covered through `[Theory]` with three `InlineData` plus implicitly the `< 1m` tier in the first test. If we only looked at line coverage, every line would have executed, but branch coverage would still be incomplete — exactly the illustration the lesson asks for.

The collection expression `[...]` for surcharges is a C# 12 novelty that reads cleaner than `new[] { ... }`. Each surcharge is its own branch (`order.IsExpress ? ...`), and the tests intentionally vary these flags to cover both arms of each ternary. The final `Math.Round(..., MidpointRounding.AwayFromZero)` encodes a business rounding rule that is a frequent source of production bugs; the `47.25` test pins the behavior. The `GeneratedMapper` class is marked `[ExcludeFromCodeCoverage]` to simulate autogenerated code that must disappear from the report; the `coverlet.runsettings` filter duplicates the exclusion by the `*Generated*` mask. Together they demonstrate the two exclusion strategies from the lesson: a pointwise attribute and a mass filter. The tests use `[Fact]` for concrete scenarios and `[Theory]/[InlineData]` for the parameterized weight tiers — the standard xUnit combination, and coverlet will collect all three metrics from them. No mocking frameworks are needed: the calculator is a pure function, which simplifies both the tests and the interpretation of coverage.

### Урок M02-L08: enum и кортежи (кратко) / enum and tuples (brief)

**Время / Time:** 30 мин теория + 45 мин практика

#### Теория / Theory

**enum** — это тип-значение, который задаёт набор именованных констант. Представьте себе переключатель режимов в пульте: вместо того чтобы помнить «0 — это выключено, 1 — сон, 2 — работа», вы видите понятные слова `Off`, `Sleep`, `Work`. enum делает именно это: сопоставляет числу (по умолчанию `int`, начиная с 0) удобное имя. Под капотом каждая константа — это просто число, поэтому приведение к `int` выполняется явно: `(int)PowerMode.Work`. Базовый тип можно сменить: `enum PowerMode : byte { Off, Sleep, Work }`, что полезно для экономии памяти в массивах флагов или при сериализации в бинарный формат.

Особый случай — атрибут `[Flags]`. Он сообщает компилятору и среде, что значения можно комбинировать через побитовые операции `|` (ИЛИ). Классическая аналогия — тумблеры на панели: можно включить «читать» и «писать» одновременно. Чтобы комбинации работали корректно, значения должны быть степенями двойки: `1, 2, 4, 8...`. Тогда `Read | Write` даёт уникальное число `5`, а метод `HasFlag` или оператор `&` позволяет проверить, установлен ли конкретный бит. Без `[Flags]` метод `ToString()` покажет просто число `5`; с ним — красивую строку `Read, Write`.

**Кортежи (tuples)** — это лёгкие структуры данных, группирующие несколько значений без объявления отдельного типа. Аналогия: бумажный пакет с подписанными отделениями — положил `(42, "answer")`, достал по имени. Начиная с C# 7 кортежи поддерживают именованные поля: `(int Code, string Message) result = (404, "Not Found")`. Доступ к полям — `result.Code` или `result.Message`. Главная сила — **деконструкция**: можно разобрать кортеж в отдельные переменные одной строкой `var (code, msg) = GetResult();`. Это делает кортежи идеальными для возврата нескольких значений из метода без `out`-параметров.

Когда выбрать кортеж, а когда `record` или `class`? Правило простое: кортеж — это «временная упаковка» для передачи 2–4 значений внутри одного вызова или между близкими методами, где имена полей не несут бизнес-смысла. `record` стоит использовать, когда у данных есть стабильная семантика (например, `Point`, `Money`), вы хотите сравнение по значению, `with`-выражения и документацию в виде именованного типа. `class` — когда нужна изменяемость, наследование, ссылочная семантика или богатое поведение. Кортеж не заменяет тип: у него нет методов, наследования и явной документации, его поля видны только там, где известна их структура.

#### Theory (EN)

An **enum** is a value type that defines a set of named constants. Think of a remote control with a mode switch: instead of remembering "0 means off, 1 means sleep, 2 means work", you read readable words `Off`, `Sleep`, `Work`. An enum does exactly this — it maps a number (by default an `int`, starting at 0) to a friendly name. Under the hood each constant is just a number, so casting to `int` is explicit: `(int)PowerMode.Work`. You can change the underlying type: `enum PowerMode : byte { Off, Sleep, Work }`, which is useful to save memory in flag arrays or when serializing to a binary format.

A special case is the `[Flags]` attribute. It tells the compiler and runtime that values can be combined with bitwise `|` (OR). The classic analogy is a row of toggles on a panel: you can switch "read" and "write" on at the same time. For combinations to work correctly the values must be powers of two: `1, 2, 4, 8...`. Then `Read | Write` produces a unique number `5`, and the `HasFlag` method or the `&` operator lets you check whether a specific bit is set. Without `[Flags]` the `ToString()` method would just show the number `5`; with it you get a readable string `Read, Write`.

**Tuples** are lightweight data structures that group several values without declaring a separate type. The analogy: a paper bag with labelled compartments — you drop in `(42, "answer")` and pull items out by name. Since C# 7 tuples support named fields: `(int Code, string Message) result = (404, "Not Found")`. You access fields as `result.Code` or `result.Message`. The main power is **deconstruction**: you can split a tuple into separate variables in a single line `var (code, msg) = GetResult();`. This makes tuples ideal for returning several values from a method without `out` parameters.

When should you pick a tuple over a `record` or a `class`? The rule is simple: a tuple is a "temporary wrapper" for passing 2–4 values inside one call or between closely related methods, where field names do not carry business meaning. Use a `record` when the data has stable semantics (for example `Point`, `Money`), you want value-based equality, `with` expressions, and documentation in the form of a named type. Use a `class` when you need mutability, inheritance, reference semantics, or rich behavior. A tuple does not replace a type: it has no methods, no inheritance, and no explicit documentation; its fields are visible only where the structure is known.

#### Пример кода / Code Example
```csharp
// C# 12 / .NET 8 — enums and tuples / enum и кортежи
// Top-level statements / Top-level инструкции

using System;

// --- enum: именованные константы / named constants ---
// Базовый тип по умолчанию — int, значения начинаются с 0
// Underlying type is int by default, values start at 0
enum PowerMode
{
    Off,    // 0
    Sleep,  // 1
    Work    // 2
}

// --- [Flags]: комбинации через побитовое ИЛИ / bitwise OR combinations ---
[Flags]
enum AccessRights
{
    None  = 0b0000,
    Read  = 0b0001, // 1
    Write = 0b0010, // 2
    Exec  = 0b0100  // 4
}

// --- Метод, возвращающий кортеж / Method returning a tuple ---
(int Code, string Message) GetResult() => (404, "Not Found");

// --- Метод с несколькими результатами / Multiple-return method ---
(string Name, AccessRights Rights) CreateUser(string name, bool canEdit) =>
    (name, canEdit ? AccessRights.Read | AccessRights.Write : AccessRights.Read);

// === Демонстрация / Demo ===
PowerMode mode = PowerMode.Work;
Console.WriteLine($"mode = {mode}, as int = {(int)mode}"); // 2

// [Flags]: комбинируем права / combine rights
AccessRights mine = AccessRights.Read | AccessRights.Write;
Console.WriteLine($"mine = {mine}");                       // Read, Write
Console.WriteLine($"can write? {mine.HasFlag(AccessRights.Write)}"); // True
// Побитовая проверка / bitwise check
bool canExec = (mine & AccessRights.Exec) == AccessRights.Exec;
Console.WriteLine($"can exec? {canExec}");                 // False

// Кортеж с именованными полями / Tuple with named fields
var http = (Code: 200, Message: "OK");
Console.WriteLine($"{http.Code} {http.Message}");

// Деконструкция / Deconstruction
var (code, msg) = GetResult();
Console.WriteLine($"{code}: {msg}");

// Деконструкция результата метода / Deconstruct a method result
var (userName, userRights) = CreateUser("Alice", canEdit: true);
Console.WriteLine($"{userName} has {userRights}");

// Сравнение: когда кортеж, когда record / when tuple vs record
var pointA = (X: 1, Y: 2);
var pointB = (X: 1, Y: 2);
Console.WriteLine($"tuples equal by value? {pointA == pointB}"); // True

record Point(int X, int Y);  // именованный тип со стабильной семантикой
// Named type with stable semantics + value equality + with-expressions
Point p1 = new(1, 2);
Point p2 = new(1, 2);
Console.WriteLine($"records equal by value? {p1 == p2}"); // True
Point moved = p1 with { X = 5 };
Console.WriteLine($"moved = {moved}");                   // Point { X = 5, Y = 2 }
```

#### Best Practices
- Используйте `enum`, когда набор значений конечен и стабилен; не заменяйте им строки там, где важна локализация.
- Для `[Flags]` всегда задавайте степени двойки и включайте значение `None = 0`.
- Возвращайте кортеж только для 2–4 значений внутри одного вызова; для широкой бизнес-семантики заводите `record`.
- Use `enum` when the set of values is finite and stable; do not replace strings with enums where localization matters.
- For `[Flags]` always use powers of two and include a `None = 0` member.
- Return a tuple only for 2–4 values within a single call; introduce a `record` for broader business semantics.

#### Частые ошибки / Common Mistakes
- Приведение `enum` к `int` неявно — ошибка компиляции → выполняйте явное приведение `(int)mode`.
- Забыли степень двойки в `[Flags]` → комбинации сливаются; задавайте `1, 2, 4, 8...`.
- Проверка флага через `==` вместо `HasFlag` или `&` → теряются комбинации; используйте `HasFlag` или `(x & flag) == flag`.
- Имя поля кортежа теряется при передаче через нетипизированный `object` → избегайте упаковки кортежей, передавайте типизированно.
- Implicit `enum`-to-`int` cast fails to compile → use an explicit cast `(int)mode`.
- Forgot powers of two in `[Flags]` → combinations collide; use `1, 2, 4, 8...`.
- Checking a flag with `==` instead of `HasFlag` or `&` → combinations lost; use `HasFlag` or `(x & flag) == flag`.
- Tuple field name is lost when boxed as `object` → avoid boxing tuples, pass them typed.

### Урок M03-L04: break/continue/return / break/continue/return

**Время / Time:** 30 мин теория + 45 мин практика

#### Теория / Theory

Управление потоком выполнения — одна из базовых задач в любом языке, и в C# для «переходов» (jump statements) есть три главных инструмента: `break`, `continue` и `return`. Они выглядят простыми, но именно от них зависит, насколько читаемым и предсказуемым будет ваш код.

**break** — это «аварийный выход». Он немедленно завершает ближайший охватывающий цикл (`for`, `foreach`, `while`, `do-while`) или ветку `switch` (а в C# 8+ — и `switch` выражение не нуждается в `break`, но `switch` оператор — нуждается). Аналогия: вы идёте по магазину с длинным списком покупок, нашли нужный товар и выходите из зала — дальше список не досматриваете. Важный нюанс: `break` действует только на один, самый внутренний блок. Если вы внутри двойного цикла, внешний цикл продолжит работу.

**continue** — «пропустить и идти дальше». Он завершает текущую итерацию цикла и переходит к следующей (к проверке условия в `while`/`do-while` или к шагу счётчика в `for`). Аналогия: конвейер с деталями — бракованную деталь вы снимаете с ленты, но конвейер не останавливаете. На `foreach` `continue` просто переходит к следующему элементу коллекции. Внутри `switch` `continue` не используется для перехода между ветками — для этого (в старых версиях) служил `goto`, а в современном C# ветки `switch` и так не «проваливаются».

**return** — «выйти из метода целиком». Он завершает не итерацию и не цикл, а весь метод, optionally возвращая значение. Если метод объявлен как `void`, пишем просто `return;`. Если метод возвращает тип `T`, то `return выражение;` обязано вернуть совместимый тип. Аналогия: вы ушли из совещания, не дождавшись конца — даже если вас попросили что-то посчитать внутри совещания, вы уже не вернётесь. `return` можно вызывать из любого места метода, в том числе изнутри цикла — это удобный ранний выход (early return), который часто улучшает читаемость, убирая вложенность.

**Отличие от throw.** `throw` тоже прерывает выполнение, но принципиально иначе: он сигнализирует об **исключительной ситуации** и запускает механизм поиска `catch`-блоков вверх по стеку вызовов. Если `catch` не найден — приложение падает. `break`/`continue`/`return` — это **нормальный** контроль потока, они не несут семантики ошибки. Правило: если ситуация ожидаемая и часть логики (например, «элемент не найден — выходим из поиска») — используйте `break`/`return`. Если же произошло что-то, что вызывающая сторона не сможет корректно обработать как обычный результат (файл не найден, деление на ноль, нарушен инвариант) — `throw`. Не злоупотребляйте исключениями как способом вернуть «особый» результат: это медленно и скрывает поток выполнения.

**Метки во вложенных циклах.** Иногда нужно выйти сразу из внешнего цикла, находясь глубоко внутри внутреннего. В C# нет «именованных циклов» в стиле Java, но можно использовать `goto` с меткой или паттерн «флаг найдено». Чаще всего читаемое решение — вынести вложенный цикл в отдельный метод и использовать `return`, либо ввести булев флаг. Прямой `goto` допустим для выхода из многоуровневых циклов, но применяйте его редко и с комментариями. Альтернатива — LINQ с `.FirstOrDefault()` или `.Any()`, который сам «рано» останавливается.

**Современный C# 12+.** Pattern matching и выражения (`switch` expression, `is` pattern) во многих случаях заменяют старый `switch` + `break`. Используйте `break` там, где работаете с классическим оператором `switch`, и предпочитайте выражения там, где результат — значение. Top-level statements позволяют писать `return` на уровне программы (точка входа `Main`).

#### Theory (EN)

Controlling the flow of execution is a fundamental task in any language, and in C# the three main "jump statements" are `break`, `continue`, and `return`. They look simple, but they are exactly what determines how readable and predictable your code is.

**break** is an "emergency exit." It immediately terminates the nearest enclosing loop (`for`, `foreach`, `while`, `do-while`) or a `switch` section (in C# 8+, a `switch` expression does not need `break`, but a `switch` statement does). Analogy: you walk through a store with a long shopping list, find the item you need, and leave — you do not keep scanning the rest of the list. Important detail: `break` only affects the single innermost construct. If you are inside a nested loop, the outer loop keeps running.

**continue** is "skip and move on." It ends the current iteration of a loop and jumps to the next one (to the condition check in `while`/`do-while`, or to the increment step in `for`). Analogy: a conveyor belt with parts — you pull a defective part off the belt, but you do not stop the belt. In a `foreach`, `continue` simply moves to the next element of the collection. Inside a `switch`, `continue` is not used to move between sections — older C# used `goto` for fall-through, and modern C# `switch` sections do not fall through anyway.

**return** is "leave the method entirely." It terminates not an iteration or a loop, but the whole method, optionally returning a value. If the method is declared `void`, you write just `return;`. If the method returns type `T`, `return expression;` must return a compatible type. Analogy: you leave a meeting before it ends — even if someone asked you to compute something during the meeting, you are not coming back. `return` can be called from anywhere in a method, including from inside a loop — this is a convenient early return that often improves readability by reducing nesting.

**Difference from throw.** `throw` also interrupts execution, but in a fundamentally different way: it signals an **exceptional condition** and triggers the search for `catch` blocks up the call stack. If no `catch` is found, the application crashes. `break`/`continue`/`return` are **normal** flow control and carry no error semantics. Rule of thumb: if the situation is expected and part of the logic (for example, "item not found — exit the search"), use `break`/`return`. If something happened that the caller cannot reasonably treat as an ordinary result (file not found, division by zero, broken invariant), use `throw`. Do not abuse exceptions as a way to return a "special" result: it is slow and hides the flow of the program.

**Labels in nested loops.** Sometimes you need to break out of an outer loop while deep inside an inner one. C# does not have "named loops" in the Java style, but you can use `goto` with a label, or the "found flag" pattern. The most readable solution is often to extract the nested loop into a separate method and use `return`, or to introduce a boolean flag. A direct `goto` is acceptable for escaping multi-level loops, but use it rarely and with comments. An alternative is LINQ with `.FirstOrDefault()` or `.Any()`, which "short-circuits" on its own.

**Modern C# 12+.** Pattern matching and expressions (`switch` expression, `is` pattern) replace the old `switch` + `break` in many cases. Use `break` where you work with a classic `switch` statement, and prefer expressions where the result is a value. Top-level statements allow `return` at the program level (the `Main` entry point).

#### Пример кода / Code Example

```csharp
// C# 12+ / .NET 8 — top-level statements
// Демонстрация break, continue, return и отличия от throw
// Demonstration of break, continue, return, and the difference from throw

using System;
using System.Collections.Generic;
using System.Linq;

// --- break: найти первое число > 100 и выйти из цикла ---
// --- break: find the first number > 100 and exit the loop ---
int FindFirstLarge(IEnumerable<int> numbers)
{
    foreach (var n in numbers)
    {
        if (n > 100)
        {
            return n;          // ранний выход из метода / early return from the method
        }
    }
    return -1;                 // "не найдено" — обычный результат, НЕ исключение / "not found" — ordinary result, NOT an exception
}

// --- continue: пропустить чётные, просуммировать нечётные ---
// --- continue: skip even numbers, sum odd ones ---
int SumOdd(int[] values)
{
    int sum = 0;
    foreach (var v in values)
    {
        if (v % 2 == 0)
        {
            continue;          // переходим к следующему элементу / move to the next element
        }
        sum += v;
    }
    return sum;
}

// --- break во вложенном цикле + метка через goto ---
// --- break in a nested loop + label via goto ---
bool ContainsPair(int[][] matrix, int target)
{
    foreach (var row in matrix)
    {
        foreach (var cell in row)
        {
            if (cell == target)
            {
                return true;  // самый читаемый выход из двух циклов сразу / the most readable exit from both loops at once
            }
        }
    }
    return false;
}

// --- классический switch с break ---
// --- classic switch with break ---
string DescribeDay(DayOfWeek day) => day switch
{
    DayOfWeek.Saturday or DayOfWeek.Sunday => "Weekend / Выходной",
    _ => "Workday / Будний день"
    // switch expression: break НЕ нужен / switch expression: break is NOT needed
};

// --- throw vs return: когда что использовать ---
// --- throw vs return: when to use which ---
int Divide(int a, int b)
{
    if (b == 0)
    {
        throw new DivideByZeroException("Делитель равен нулю. / Divisor is zero.");
        // это исключительная ситуация — throw / this is an exceptional condition — throw
    }
    return a / b;
}

// --- demo ---
var numbers = new[] { 1, 5, 12, 101, 7, 200 };
Console.WriteLine($"First large: {FindFirstLarge(numbers)}");          // 101
Console.WriteLine($"Sum of odd: {SumOdd(numbers)}");                   // 1 + 5 + 7 = 13
Console.WriteLine($"Contains 101: {ContainsPair(new[] { new[] { 1, 2 }, new[] { 101 } })}"); // True
Console.WriteLine($"Day: {DescribeDay(DayOfWeek.Saturday)}");          // Weekend / Выходной

try
{
    Console.WriteLine(Divide(10, 0));
}
catch (DivideByZeroException ex)
{
    Console.WriteLine($"Caught: {ex.Message}");                        // ловим исключение / catch the exception
}
```

#### Best Practices

- Предпочитайте ранний `return` глубокой вложенности: меньше `if-else` уровней — легче читать. / Prefer early `return` over deep nesting: fewer `if-else` levels — easier to read.
- Используйте `break` и `continue` для явного управления циклом, но не превращайте тело цикла в «спагетти» из множества переходов. / Use `break` и `continue` for explicit loop control, but do not turn the loop body into "spaghetti" of many jumps.
- Не используйте исключения (`throw`) как способ вернуть «особый» результат метода — это медленно и скрывает логику. / Do not use exceptions (`throw`) as a way to return a "special" result — it is slow and hides the logic.
- В современном C# предпочитайте `switch` expression там, где результат — значение: короче и не требует `break`. / In modern C#, prefer `switch` expression where the result is a value: shorter and needs no `break`.
- Для выхода из вложенных циклов выносите внутренний цикл в отдельный метод и используйте `return` — чище, чем `goto`. / To exit nested loops, extract the inner loop into a separate method and use `return` — cleaner than `goto`.

#### Частые ошибки / Common Mistakes

- `break` во внешнем цикле, ожидая выхода из обоих → `break` выходит только из самого внутреннего цикла. Вынесите логику в метод и используйте `return`. (RU)
- Использование `throw` для возврата «не найдено» из метода-поиска → возвращайте `-1`, `null` или `bool` через `out`; исключения — для действительно исключительных ситуаций. (RU)
- Забытый `break` в классическом `switch` операторе → в C# неявного fall-through нет, но отсутствие `break`/`return`/`goto` в непустой ветке вызывает ошибку компиляции; всегда завершайте ветку явно. (RU)
- `return` с значением в `void`-методе → компилятор выдаст ошибку; в `void` пишите только `return;`. (RU)
- `continue` в `switch` для перехода к следующей ветке → `continue` работает только в циклах, не в `switch`; используйте правильную конструкцию. (RU)
- Using `break` in an outer loop expecting to exit both → `break` exits only the innermost loop. Extract logic into a method and use `return`. (EN)
- Using `throw` to return "not found" from a search method → return `-1`, `null`, or a `bool` via `out`; reserve exceptions for genuinely exceptional situations. (EN)
- Forgetting `break` in a classic `switch` statement → C# has no implicit fall-through, but a non-empty section without `break`/`return`/`goto` is a compile error; always end a section explicitly. (EN)
- `return` with a value in a `void` method → the compiler will error; in `void` write only `return;`. (EN)
- `continue` inside `switch` to move to the next section → `continue` works only in loops, not in `switch`; use the right construct. (EN)

### Урок M01-L06: Первый Hello World, отладка, NuGet-базис / First Hello World, debugging, NuGet basics

**Время / Time:** 30 мин теория + 45 мин практика

#### Теория / Theory

В этом уроке мы замыкаем базовый цикл разработки на .NET: пишем первую программу, учимся её отлаживать и подключаем внешние библиотеки через NuGet. Это три навыка, без которых ни один реальный проект не сдвинется с места.

**Hello World с args.** Минимальная программа на C# 12 в .NET 8 может состоять из одной строки благодаря top-level statements — неявному методу `Main`. Когда вы запускаете `dotnet run arg1 arg2`, аргументы попадают в массив `args`, доступный напрямую в коде верхнего уровня. Представьте args как список поручений, которые вы передаёте курьеру перед выездом: программа читает их и действует соответственно. Если аргументов нет, массив пустой (не `null`), поэтому безопасно проверять `args.Length`. Обработка аргументов командной строки — стандартный способ параметризовать консольные утилиты: имя файла, режим работы, ключ шифрования.

**Точки останова (breakpoints).** Отладчик позволяет暂停ить выполнение на любой строке и осмотреть состояние. Точка останова — это красный маркер слева от строки кода (в Visual Studio, VS Code, Rider). Достигнув её, программа замораживается, и вы можете посмотреть значения переменных, стек вызовов и состояние памяти. Аналогия: вы читаете книгу и кладёте закладку — при возвращении точно знаете, где остановились. Ставьте брейкпойнты там, где подозреваете ошибку: на входе в метод, перед подозрительным вычислением, внутри цикла.

**Step Into / Step Over / Watch.** После остановки вы шагаете по коду. **Step Into (F11)** заходит внутрь вызываемого метода — полезно, когда нужно понять, что происходит внутри функции. **Step Over (F10)** выполняет строку целиком, не заходя внутрь вызовов — удобно для библиотечных методов. **Step Out** выходит из текущего метода обратно к вызывающему. Окно **Watch** позволяет добавлять переменные и выражения для постоянного наблюдения — они обновляются на каждом шаге. Аналогия: Step Into — открыть коробку и заглянуть внутрь; Step Over — перенести коробку целиком, не открывая; Watch — положить несколько предметов на весы и следить за весом на каждом шаге.

**NuGet как пакетный менеджер.** NuGet — это система управления пакетами для .NET, аналог npm для JavaScript или pip для Python. Пакет (nupkg) — это ZIP-архив с скомпилированной DLL, метаданными и, возможно, другими файлами. Центральный репозиторий nuget.org содержит сотни тысяч библиотек: логирование (Serilog), JSON (Newtonsoft.Json, System.Text.Json), HTTP (RestSharp), тестирование (xUnit) и многое другое. NuGet решает зависимости автоматически: если пакет A требует пакет B версии 2.1, NuGet подтянет и B.

**dotnet add package.** Команда `dotnet add package <имя> --version <версия>` добавляет ссылку на пакет в проект. Альтернатива — установка через Visual Studio (Manage NuGet Packages) или редактирование `.csproj` вручную. Флаг `--version` фиксирует конкретную версию; без него берётся последняя стабильная.

**PackageReference.** Начиная с .NET Core / .NET 5+, пакеты описываются в `.csproj` через элемент `<PackageReference Include="Имя" Version="X.Y.Z" />`. Это пришло на смену старым `packages.config`. Преимущества: единый файл проекта, транзитивное восстановление зависимостей, удобная работа в системах контроля версий. Пакеты восстанавливаются автоматически при `dotnet restore`, `dotnet build`, `dotnet run`. Конфликт версий разрешается по принципу «ближайшего выигрыша» (nearest wins): прямая ссылка переопределяет транзитивную.

#### Theory (EN)

In this lesson we close the basic .NET development loop: write the first program, learn to debug it, and connect external libraries via NuGet. These are three skills without which no real project moves forward.

**Hello World with args.** A minimal C# 12 program on .NET 8 can be a single line thanks to top-level statements — an implicit `Main` method. When you run `dotnet run arg1 arg2`, the arguments land in the `args` array, available directly in top-level code. Think of args as a list of errands you hand to a courier before departure: the program reads them and acts accordingly. With no arguments the array is empty (not `null`), so checking `args.Length` is safe. Command-line argument handling is the standard way to parameterize console tools: a file name, a mode, an encryption key.

**Breakpoints.** The debugger lets you pause execution on any line and inspect state. A breakpoint is a red marker in the editor margin (Visual Studio, VS Code, Rider). When the program reaches it, execution freezes and you can examine variable values, the call stack, and memory. Analogy: you read a book and place a bookmark — on return you know exactly where you stopped. Place breakpoints where you suspect a bug: at method entry, before a suspicious computation, inside a loop.

**Step Into / Step Over / Watch.** After a stop you step through the code. **Step Into (F11)** enters the called method — useful when you need to see what happens inside a function. **Step Over (F10)** executes the whole line without descending into calls — handy for library methods. **Step Out** leaves the current method back to the caller. The **Watch** window lets you pin variables and expressions for constant observation — they refresh at every step. Analogy: Step Into is opening a box and looking inside; Step Over is moving the whole box without opening it; Watch is putting a few objects on a scale and tracking the weight at each step.

**NuGet as a package manager.** NuGet is the package manager for .NET, analogous to npm for JavaScript or pip for Python. A package (nupkg) is a ZIP archive with a compiled DLL, metadata, and possibly other files. The central repository nuget.org holds hundreds of thousands of libraries: logging (Serilog), JSON (Newtonsoft.Json, System.Text.Json), HTTP (RestSharp), testing (xUnit), and much more. NuGet resolves dependencies automatically: if package A needs package B version 2.1, NuGet pulls B too.

**dotnet add package.** The command `dotnet add package <name> --version <version>` adds a package reference to the project. Alternatives are installing through Visual Studio (Manage NuGet Packages) or editing `.csproj` by hand. The `--version` flag pins a specific version; without it the latest stable is taken.

**PackageReference.** Since .NET Core / .NET 5+, packages are declared in `.csproj` via the `<PackageReference Include="Name" Version="X.Y.Z" />` element. This replaced the old `packages.config`. Benefits: a single project file, transitive dependency restoration, convenient version-control workflow. Packages restore automatically on `dotnet restore`, `dotnet build`, `dotnet run`. Version conflicts are resolved by "nearest wins": a direct reference overrides a transitive one.

#### Пример кода / Code Example

```csharp
// Первый Hello World с обработкой аргументов / First Hello World with argument handling
// C# 12 / .NET 8 — top-level statements
// Запуск / Run: dotnet run -- Alice --count 3

// args доступен напрямую в коде верхнего уровня / args is available directly in top-level code
if (args.Length == 0)
{
    Console.WriteLine("Привет, мир! / Hello, world!");
    Console.WriteLine("Подсказка / Hint: dotnet run -- <name> [--count N]");
    return;
}

// Разбор аргументов через pattern matching / Parse args via pattern matching
string name = "Мир / World";
int count = 1;

foreach (var arg in args)
{
    // Шаблонное сопоставление с when-фильтром / Pattern matching with when guard
    switch (arg)
    {
        case "--count" or "-n":
            // Следующий аргумент — число / Next arg is the count
            break;
        case var n when int.TryParse(n, out var parsed) && parsed is > 0 and <= 100:
            count = parsed;
            break;
        case var s when s.StartsWith("--") is false:
            name = s;
            break;
    }
}

// Используем NuGet-пакет Spectre.Console для красивого вывода (потребует dotnet add package Spectre.Console)
// Using the Spectre.Console NuGet package for pretty output (requires dotnet add package Spectre.Console)
// Чтобы пример работал без пакета — выводим обычным Console.WriteLine:
// To keep the sample working without the package — use plain Console.WriteLine:
for (int i = 0; i < count; i++)
{
    // Интерполяция строк + выравнивание / String interpolation with alignment
    Console.WriteLine($"[{i + 1,2}] Привет, {name}! / Hello, {name}!");
}

// Наглядная точка для отладки: поставьте сюда breakpoint (F9)
// A convenient debugging spot: set a breakpoint here (F9)
var summary = $$"""
Итог / Summary:
  - Имя / Name : {{name}}
  - Повторов / Repetitions : {{count}}
  - Аргументов получено / Args received : {{args.Length}}
""";

Console.WriteLine(summary);
```

Пример `.csproj` с PackageReference / Example `.csproj` with PackageReference:

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <OutputType>Exe</OutputType>
    <TargetFramework>net8.0</TargetFramework>
    <ImplicitUsings>enable</ImplicitUsings>
    <Nullable>enable</Nullable>
    <LangVersion>latest</LangVersion>
  </PropertyGroup>

  <!-- PackageReference заменяет packages.config / PackageReference replaces packages.config -->
  <ItemGroup>
    <PackageReference Include="Spectre.Console" Version="0.48.0" />
  </ItemGroup>
</Project>
```

Команды CLI / CLI commands:

```bash
# Создать проект / Create project
dotnet new console -n HelloWorldArgs

# Добавить пакет / Add package
dotnet add package Spectre.Console --version 0.48.0

# Восстановить зависимости / Restore dependencies
dotnet restore

# Запустить с аргументами / Run with arguments
dotnet run -- Alice --count 3
```

#### Best Practices

- Включайте `<Nullable>enable</Nullable>` и `<ImplicitUsings>enable</ImplicitUsings>` в каждом новом проекте — это современный безопасный стандарт .NET 8.
- Фиксируйте версии пакетов в `<PackageReference Version="...">` явно; избегайте плавающих версий вроде `*` в production-коде.
- Размещайте точки останова на строках с реальной логикой, а не на пустых строках или закрывающих скобках — отладчик может вести себя непредсказуемо.
- Используйте `Watch` для сложных выражений (`user.Orders.Count`, `items.FirstOrDefault()?.Price`) вместо того, чтобы гадать о значениях по шагам.
- Восстанавливайте пакеты (`dotnet restore`) перед сборкой в CI — это делает сборку детерминированной и независимой от локального кэша.

- Enable `<Nullable>enable</Nullable>` and `<ImplicitUsings>enable</ImplicitUsings>` in every new project — the modern safe .NET 8 default.
- Pin package versions explicitly in `<PackageReference Version="...">`; avoid floating versions like `*` in production code.
- Place breakpoints on lines with real logic, not on blank lines or closing braces — the debugger may behave unpredictably.
- Use `Watch` for complex expressions (`user.Orders.Count`, `items.FirstOrDefault()?.Price`) instead of guessing values across steps.
- Restore packages (`dotnet restore`) before building in CI — this makes the build deterministic and independent of the local cache.

#### Частые ошибки / Common Mistakes

- Забыть, что `args` при отсутствии аргументов — пустой массив, а не `null` → всё равно проверяйте `args.Length` перед обращением по индексу, чтобы не получить `IndexOutOfRangeException`.
- Путать Step Into (F11) и Step Over (F10) → запомните правило: Into — внутрь метода, Over — мимо метода; на библиотечных методах всегда Over.
- Добавлять пакет в один проект и ждать его в другом → PackageReference действует на конкретный `.csproj`; для расшаривания вынесите общий набор в `Directory.Packages.props` (Central Package Management).
- Использовать плавающие версии (`Version="*"`) → фиксируйте точную версию, иначе сборка сломается при выходе мажорного обновления пакета.
- Игнорировать предупреждения NU1605 (конфликт версий) → изучите граф зависимостей через `dotnet list package --include-transitive` и разрешите конфликт явной ссылкой.

- Forgetting that `args` with no arguments is an empty array, not `null` → still check `args.Length` before indexing to avoid `IndexOutOfRangeException`.
- Confusing Step Into (F11) and Step Over (F10) → remember: Into descends into a method, Over skips past it; always Over on library methods.
- Adding a package to one project and expecting it in another → PackageReference applies to a specific `.csproj`; to share, move the common set to `Directory.Packages.props` (Central Package Management).
- Using floating versions (`Version="*"`) → pin an exact version, otherwise the build breaks when a major package update ships.
- Ignoring NU1605 warnings (version conflict) → inspect the dependency graph via `dotnet list package --include-transitive` and resolve the conflict with an explicit reference.
